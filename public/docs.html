クライアント実装ガイド

Fodpr に接続するクライアントを実装するためのプロトコル・投稿フォーマット・タグ仕様の詳細解説

基本形 送信タイプ ワイヤプロトコル 投稿フォーマット メディア プロフィール リポスト・引用・リアクション リプライ(スレッド) dedupeKey 署名 REST API リレー一覧

1.イベントの基本形

Fodpr の投稿(イベント)は以下のフィールドで構成されます。リレーは content の中身を解釈せず、transType ごとのストレージに追記保存します。

フィールド型説明
pubkeybytes (33)投稿者の公開鍵(secp256k1 圧縮形式)
signaturebytes (64)content に対する ECDSA 署名
transTypenumberフォーマット種別(JSON / string / binary)
contentstring本文 / ペイロード
tagsstring[]補足情報(caption: / react: など)
createdAtnumberUnix 秒タイムスタンプ

署名検証は signature = sign(privkey, sha256(content)) です。詳細は 署名 を参照。

2.送信タイプ (TransType)

イベントの content が何であるかを表す数値です。

定数値用途
TransTypeAll0x00REQ(購読)でのみ使用
TransTypeJSON0x01content が UTF-8 の JSON(プロフィール)
TransTypeString0x02content が UTF-8 の文字列(テキスト投稿・リアクション・リポスト・リプライ)
TransTypeBinary0x03content が任意のバイト列(画像/動画/ファイル投稿)

クライアントは受信イベントを以下のように振り分けます。

  • TransTypeJSON で content が JSON かつ mode === "profile" → プロフィール
  • TransTypeString で react: タグ → リアクション、reply: タグ → リプライ、repost:/quote: タグ → リポスト/引用、それ以外 → テキスト投稿
  • TransTypeBinary → メディア投稿

3.ワイヤプロトコルと送信方法

リレーとはバイナリ WebSocket フレームで通信します。テキストフレームは UTF-8 エンコードのため、公開鍵や署名のような任意バイト列(0x80 以上)をそのまま運べないためです。

3.1 パケット種別

種別バイトメッセージ方向
0x01EVENT(イベント投稿)クライアント → サーバー
0x02REQ(購読要求)クライアント → サーバー
0x03DEL(削除要求)クライアント → サーバー
0x81PUSH(イベント配信)サーバー → クライアント

3.2 イベント本体のバイナリレイアウト

すべてビッグエンディアンです。

transType(2) | createdAt(8) | pubkey(33) | tagCount(2) | (tagLen(2) | tag) * tagCount | contentLen(4) | content | signature(64)
  • createdAt: Unix タイムスタンプ(秒, uint64)
  • pubkey: 圧縮公開鍵 33 バイト
  • tags: UTF-8 文字列の配列
  • content: UTF-8 バイト列(TransTypeBinary でもバイナリのまま配信)
  • signature: content の SHA-256 に対する ECDSA 署名 64 バイト

3.3 投稿パケット (EVENT)

encodeEvent の出力は「本体」なので、送信時は先頭に種別バイト 0x01 を付けます。

const payload = Protocol.encodeEvent(event);       // イベント本体
const frame = new Uint8Array(1 + payload.length);  // 種別バイト + 本体
frame[0] = 0x01;                                   // MsgTypeEvent
frame.set(payload, 1);
ws.send(frame.buffer);                             // バイナリフレームで送信

3.4 購読 (REQ)

接続確立後に一度 REQ を送ると、保存済みイベントが PUSH され、以後の新着も PUSH されます。

MsgTypeReq(1) | subIdLen(2) | subId | transType(2) | tagKeyLen(2) | tagKey | tagValLen(2) | tagVal
const req = {
  subId: 'sub_web_' + Date.now(),
  transType: TransTypeAll, // すべてのタイプを購読
  tagKey: '',
  tagVal: '',
};
ws.send(Protocol.encodeReq(req)); // 先頭に 0x02 を含む

タグ絞り込みも可能です。例: caption: タグを持つメディアだけを購読する場合、tagKey = "caption" を指定します。

4.投稿フォーマット

4.1 テキスト投稿 (TransTypeString)

transType = 0x02、content = 本文、tags = []。署名対象は content の UTF-8 バイト列です。

const content = '今日もにゃんこ日和。';
const sig = await CryptoUtils.signMessage(privKey, new TextEncoder().encode(content));
const event = {
  transType: TransTypeString,
  createdAt: Math.floor(Date.now() / 1000),
  pubkey: pubkeyBytes,      // 33 バイト圧縮公開鍵
  tags: [],
  content,
  signature: CryptoUtils.hexToBytes(sig),
};
sendEventToRelay(event);    // Protocol.encodeEvent + 0x01 前置 + バイナリ送信

4.2 プロフィール投稿 (TransTypeJSON)

mode: "profile" を必須とします。クライアントはこれでプロフィールと判定します。

{
  "mode": "profile",
  "name": "表示名 (必須)",
  "about": "自己紹介 (省略可)",
  "picture": "アイコン画像の直リンク URL (省略可)"
}

表示には公開鍵ごとに createdAt が最大のプロフィールを 1 件だけ採用します。つまりプロフィールは「上書き」です。

picture は直リンク URL です。同一オリジンなら /media/file/<name> の相対パス、別オリジンのクライアントからも表示したい場合は絶対 URL を入れてください。

4.3 メディア投稿 (TransTypeBinary)

詳細は メディア を参照してください。

5.メディア投稿 (画像/動画/ファイル)

5.1 content の形式

content は <mime>:<base64> 形式です(区切りはコロン)。

<mime>:<base64>
例: image/png:iVBORw0KGgoAAAANSUhEUg...
  • <mime>: data URL の MIME 部分(data:image/png;base64,XXXX の image/png)
  • <base64>: data URL の base64 本体(区切りは コロン。 ;base64, ではない)

クライアントの描画は /^(?:img:)?([^:;,]+)(?:;base64)?[,:](.+)$/s でパースし、mime が video/ で始まれば動画、それ以外は画像/ダウンロードリンクとして表示します。

5.2 tags

タグ内容
caption:<文字列>キャプション(無ければ元ファイル名)。カードの alt / 説明文
filename:<文字列>元ファイル名(プレビューやダウンロード名)
mediatype:<image|video|file>種別(動画かどうかの判定)

5.3 送信コード

const dm = /^data:([^;]+);base64,(.+)$/s.exec(mediaDataUrl);
const mime = dm[1];
const base64 = dm[2];
const mediaContent = `${mime}:${base64}`;
const sig = await CryptoUtils.signMessage(privKey, new TextEncoder().encode(mediaContent));
const event = {
  transType: TransTypeBinary,
  createdAt: Math.floor(Date.now() / 1000),
  pubkey: pubkeyBytes,
  tags: [
    `caption:${caption}`,
    `filename:${filename}`,
    `mediatype:${mediaType}`, // "image" | "video" | "file"
  ],
  content: mediaContent,
  signature: CryptoUtils.hexToBytes(sig),
};
sendEventToRelay(event);

5.4 圧縮と上限

  • 画像: 上限 12MB。長辺 1600px までリサイズ+再エンコード
  • 動画: 上限 50MB。data URL 化して投稿、サムネイルを抽出
  • その他ファイル: 上限 12MB。そのまま data URL 化
メディア本体はイベントの content に base64 で入るため、リレーの保存サイズもその分大きくなります。

6.プロフィール画像のアップロード

プロフィールの picture に使う直リンク URL は、同一オリジンのメディアサーバーで発行できます。

POST /media/upload        (Content-Type: image/png で画像本体を POST)
→ 200 {"url":"/media/file/<32hex>.png","mime":"image/png","isVideo":false,"isImage":true}

GET  /media/file/<name>   保存済み画像の配信
const res = await fetch('/media/upload', {
  method: 'POST',
  headers: { 'Content-Type': blob.type },
  body: blob,
});
const { url } = await res.json(); // 例: "/media/file/abcd1234....png"
// この url をプロフィール JSON の picture に入れて TransTypeJSON で投稿する

7.リポスト・引用・リアクション

いずれも TransTypeString で送られる補助イベントです。対象イベントは dedupeKey で指定します。

種別contenttags
リアクション絵文字(例 ❤️)react:<dedupeKey>
リポスト空文字repost:<dedupeKey>
引用リポスト自分のコメントquote:<dedupeKey>
// リアクション
const sig = await CryptoUtils.signMessage(privKey, new TextEncoder().encode('❤️'));
sendSignedEvent(TransTypeString, '❤️', sig, [`react:${dedupeKeyOfTarget}`]);

// リポスト (content が空でも署名対象は空文字の UTF-8 バイト列)
const sig2 = await CryptoUtils.signMessage(privKey, new TextEncoder().encode(''));
sendSignedEvent(TransTypeString, '', sig2, [`repost:${dedupeKeyOfTarget}`]);

// リプライ (content = 返信本文、署名対象は本文の UTF-8 バイト列)
const sig3 = await CryptoUtils.signMessage(privKey, new TextEncoder().encode('返信本文'));
sendSignedEvent(TransTypeString, '返信本文', sig3, [`reply:${dedupeKeyOfTarget}`]);

7.2 リプライ / スレッド表示

リプライは reply:<dedupeKey> タグの付いた TransTypeString です。対象イベントの直下に「返信 n 件」としてスレッド表示され、返信の返信も再帰的に表示されます。自分の投稿の右上にある … (メニュー) ボタンからも投稿を削除できます。

  • 対象イベントが未取得の場合は「返信先が見つからない投稿」欄にフォールバック表示されます
  • 自分のプロフィール画面の投稿一覧には、自分のリプライも含めて表示されます
  • リプライの送信はコンポーザの「返信先」バナーから行えます(テキストのみ、Ctrl/Cmd+Enter で投稿)
リレーは過去に PUSH 済みのイベントを取り消しません。そのためクライアントは削除済みイベントの dedupeKey をローカルで記憶し、フィードから除外しています。

8.dedupeKey(イベントの一意キー)

重複排除に使うキーです。イベントの署名まで含めることで「同一秒に複数投稿」しても重複して弾かないようにしています。

dedupeKey = pubkeyHex + ":" + transType + ":" + createdAt + ":" + signatureHex

リポスト / 引用 / リアクションの対象指定(タグの値)にもこの文字列を使います。

投稿削除(DEL)時には createdAt と content の SHA-256 ハッシュ(contentHash)を指定します。

9.署名

署名はすべて ECDSA(secp256k1、compact 形式 64 バイト)です。signMessage は content の SHA-256 ダイジェストに対して署名します。

署名対象のバイト列は必ず new TextEncoder().encode(content) を使うこと。サーバー側の検証と一致するために重要です。
// 鍵生成
const privKey = CryptoUtils.generatePrivateKey();          // 64 桁 HEX
const pubkey  = CryptoUtils.getPublicKey(privKey);         // 圧縮公開鍵 HEX

// 署名 (content の SHA-256 に署名)
const sig = await CryptoUtils.signMessage(privKey, new TextEncoder().encode(content));

// 検証
const ok = await CryptoUtils.verifySignature(pubkey, new TextEncoder().encode(content), sig);

10.REST API(サーバー側)

クライアントから直接リレーへ接続できない環境向けに、REST API も提供されています。/api/docs に詳しい仕様があります。

エンドポイントメソッド説明
/api/keygenPOST秘密鍵を新規生成
/api/notePOSTテキスト投稿(tags で reply: / quote: / react: / repost: を指定可能)
/api/mediaPOSTメディア投稿(JSON base64 / multipart 両対応)
/api/deletePOST投稿削除(contentHash または content 指定)
/api/eventsGET購読済みイベントの取得(limit/since/after/transType)
/api/healthGETヘルスチェック
/api/docsGETAPI ドキュメント(HTML)
# テキスト投稿の例
POST /api/note
Content-Type: application/json

{
  "privKey": "<64桁HEXの秘密鍵>",
  "content": "こんにちは",
  "tags": []
}

11.リレー一覧の保存先

ブラウザクライアントのリレー一覧は localStorage に保存されます。

localStorage.fodpr_relays = JSON.stringify(["wss://example.com/", "wss://fodpr.yoinekodo.jp/"]) // 複数可
