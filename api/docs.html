Fodpr REST API

Bot やスクリプトから Fodpr のタイムラインに投稿・削除・購読(取得)するための HTTP API。

ベース URL: https://fodpr.yoinekodo.jp/api
すべてのリクエスト・レスポンスは JSON(UTF-8)です。POST は Content-Type: application/json を 指定してください(メディア投稿の multipart/form-data 形式も対応)。 成功時は {"ok": true, ...}、失敗時は {"ok": false, "error": "..."} と HTTP ステータスを返します。

秘密鍵について

Fodpr では secp256k1 の秘密鍵(64 桁の HEX)を使って投稿に署名します。 この API では privKey フィールドに秘密鍵を渡すだけで、サーバー側で署名と送信を行います。

秘密鍵は他人に教えないでください。鍵が漏れるとそのアカウントのすべての投稿・削除ができてしまいます。 API は HTTPS(Cloudflare)経由で暗号化されているため通信中の盗聴は防げますが、スクリプトの保存先には十分注意してください。

1. 秘密鍵の作成 POST/api/keygen

新規の秘密鍵と公開鍵を生成します。初めて使うときはまずここで鍵を作って保存してください。

curl -X POST https://fodpr.yoinekodo.jp/api/keygen

レスポンス例:

{
  "ok": true,
  "privKey": "f0d4c1a2...64桁のHEX...",
  "pubkey": "02c0ffee...66桁のHEX(圧縮公開鍵)..."
}
フィールド説明
privKey秘密鍵(64 桁 HEX)。次回以降の投稿に使うので安全に保存してください。
pubkey公開鍵(66 桁 HEX、圧縮形式 33 バイト)。アカウントの ID にあたります。

2. テキスト投稿 POST/api/note

テキストをタイムラインに投稿します。

POST/api/note
リクエスト本文(JSON)
{
  "privKey": "64桁のHEX秘密鍵",
  "content": "こんにちは、Fodpr の世界!",
   "tags": [],            // 任意。追加タグ(例: ["react:","quote:","repost:","reply:"])
   "quote": "",            // 任意。引用リポストする対象の dedupeKey
   "reply": ""            // 任意。返信する対象の dedupeKey(自分のコメントを content に入れる)
}
レスポンス例
{
  "ok": true,
  "message": "OK: Event accepted",
  "event": {
    "dedupeKey": "pubkey:2:1785981600:署名...",
    "transType": 2,
    "createdAt": 1785981600,
    "pubkey": "02...",
    "tags": [],
    "content": "こんにちは、Fodpr の世界!",
    "signature": "..."
  }
}

event.dedupeKey はこの投稿を一意に識別するキーです。後で削除したいときや、 他のユーザーが「引用」「リアクション」するときに使う ID です。投稿時は必ず保存しておきましょう。

3. メディア投稿 POST/api/media

画像・動画・ファイルを添付して投稿します。リレーの仕様上、ファイルは base64 にしてイベントに埋め込まれます。

3a. JSON(base64)で送る場合

POST/api/media 
{
  "privKey": "64桁のHEX秘密鍵",
  "mime": "image/png",
  "data": "iVBORw0KGgoAAAANSUhEUg... (base64エンコードしたファイル本体)",
  "caption": "かわいい猫の写真",
  "filename": "cat.png"
}

3b. multipart/form-data で送る場合(curl 推奨)

curl -X POST https://fodpr.yoinekodo.jp/api/media \
  -F "privKey=64桁のHEX秘密鍵" \
  -F "caption=かわいい猫の写真" \
  -F "file=@cat.png;type=image/png"
フィールド説明
privKey秘密鍵(必須)
mime / dataJSON 形式のとき必須。MIME タイプと base64 データ
filemultipart 形式のとき必須。ファイル本体
caption任意。画像の説明文(タイムラインで表示)
filename任意。元ファイル名(省略時は file)

対応形式と上限: 画像 image/jpeg, png, webp, gif 12MB まで、動画 video/mp4, webm, mov, avi, mkv 50MB まで。

4. 投稿の削除 POST/api/delete

自分の投稿だけを削除できます。投稿したときの createdAt と、本文の SHA-256(contentHash) が必要です。

POST/api/delete 
{
  "privKey": "64桁のHEX秘密鍵",
  "createdAt": 1785981600,          // 投稿時の event.createdAt(Unix秒)
  "contentHash": "64桁HEX",         // 本文の SHA-256(または下の content でも可)
  "transType": 2                    // 任意(省略時はすべてのタイプから探す)
}

contentHash の代わりに削除する本文そのものを content フィールドで渡すこともできます (サーバーが SHA-256 を計算します)。レスポンス例: 

{ "ok": true, "message": "OK: 1 event(s) deleted", "deleted": 1 }
削除はサーバー側で永久に行われます。取り消しはできません。

5. タイムラインの取得(購読) GET/api/events

リレーの購読(REQ All)を常時受信しているため、そのまま GET /api/events を呼ぶだけで タイムラインの最新イベントを取得できます。定期的にポーリングすることで Bot の購読にも使えます。 

curl "https://fodpr.yoinekodo.jp/api/events?limit=50"
クエリパラメータ説明
limit取得件数(既定 100, 最大 1000)
sinceUnix 秒。これより後に投稿されたイベントのみ
after前回取得したイベントの dedupeKey。これより新しいイベントのみ(次のページ用)
transTypeフィルタ: 0=全, 1=JSON(プロフィール), 2=テキスト, 3=メディア
tagKey / tagValタグの絞り込み。例 mediatype / image

レスポンス例:

{
  "ok": true,
  "events": [
    {
      "dedupeKey": "pubkey:2:1785981600:署名...",
      "transType": 2,
      "createdAt": 1785981600,
      "pubkey": "02...",
      "tags": [],
      "content": "こんにちは、Fodpr の世界!",
      "signature": "..."
    }
  ],
  "count": 1,
  "relayConnected": true
}

イベントのタイプ(transType)と表示

transType意味contenttags
1 (JSON)プロフィール{"mode":"profile","name":"...","about":"...","picture":"..."}(なし)
2 (String)テキスト投稿・リアクション・リポスト・引用・リプライ本文(テキスト投稿・引用・リプライ) / 絵文字(リアクション) / 空(リポスト)react: quote: repost: reply:
3 (Binary)メディア投稿mime:base64 例 image/png:iVBOR...caption: filename: mediatype:

状態確認 GET/api/health

サーバーとリレーの接続状態を確認します。

curl https://fodpr.yoinekodo.jp/api/health
{
  "ok": true,
  "relayConnected": true,
  "relay": "ws://localhost:8000/",
  "buffered": 1284,
  "totalEvents": 1284
}

Bot の作り方(例)

Python でのテキスト投稿の例:

import json, urllib.request

KEY = "64桁のHEX秘密鍵"  # 事前に /api/keygen で作成

req = urllib.request.Request(
    "https://fodpr.yoinekodo.jp/api/note",
    data=json.dumps({"privKey": KEY, "content": "にゃーん"}).encode(),
    headers={"Content-Type": "application/json"},
)
print(json.load(urllib.request.urlopen(req)))

JavaScript(Node.js)での投稿と取得の例:

const base = "https://fodpr.yoinekodo.jp/api";

// 投稿
const res = await fetch(base + "/note", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ privKey: KEY, content: "にゃーん" }),
});
const posted = await res.json();

// 取得(投稿直後から 10 件)
const feed = await fetch(base + "/events?since=" + Math.floor(Date.now()/1000) + "&limit=10").then(r => r.json());

詳細なワイヤプロトコル(上級者向け)

この API はリレーとの通信をすべて内部で行いますが、独自クライアントを実装する場合は この API を使わずに WebSocket(バイナリフレーム)で直接リレーに接続することもできます。 イベントのバイナリ構造・タグ仕様・dedupeKey の詳細は Web クライアントの設定から「クライアント実装ガイド」をご覧ください。
